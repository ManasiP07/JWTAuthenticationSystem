# Phase 1 - Planning

## Why start with Authentication?
Almost every enterprise application begins with authentication because every request needs to answer two questions:

### Authentication
Who is the user?

Example:
Email:
manasi@gmail.com

Password:
*******

If the credentials are correct, the user is authenticated.

### Authorization

What is the authenticated user allowed to do?

Example:
Admin
    Can Create Users
    Can Delete Users

Employee
    Can View Profile

Authentication identifies the user.
Authorization determines permissions.

# Chosen Authentication Method

There are multiple authentication methods available.

| Method                 | Used For                      |
| ---------------------- | ----------------------------- |
| Session Authentication | Traditional web applications  |
| Cookie Authentication  | MVC applications              |
| JWT Authentication     | REST APIs                     |
| OAuth                  | Google, Facebook Login        |
| OpenID Connect         | Enterprise identity providers |

For this project, we chose:

> **JWT Authentication**

because it is the most common approach for modern ASP.NET Core Web APIs.

# NuGet Package Installation

While installing Entity Framework Core, we encountered a version compatibility issue.

Attempted package:
Microsoft.EntityFrameworkCore.SqlServer 10.0.10

Error:
Package supports net10.0 only.

Reason:
The project targets **.NET 9**, so Entity Framework Core **10** is incompatible.

Solution:

Install the **9.x** versions of:

* Microsoft.EntityFrameworkCore.SqlServer
* Microsoft.EntityFrameworkCore.Tools
* Microsoft.AspNetCore.Authentication.JwtBearer

This reinforced an important rule:

| Target Framework | EF Core Version |
| ---------------- | --------------- |
| .NET 8           | EF Core 8.x     |
| .NET 9           | EF Core 9.x     |
| .NET 10          | EF Core 10.x    |

# Lessons Learned

1. Choosing the correct Visual Studio project template is essential. A Console Application cannot be used to build Web APIs.
2. SQL Server and SSMS are separate tools: SQL Server is the database engine, while SSMS is the client used to manage it.
3. Entity Framework Core versions should match the target .NET version.
4. Authentication (identity) and authorization (permissions) solve different problems.
5. Using Git feature branches from the beginning encourages a professional development workflow.
